# Bond Quest — Codex Working Guide

An open-world **chemistry learning game** (ionic / covalent / metallic bonding,
dot-and-cross diagrams) with a Genshin-style action combat & reward loop.
Everything is **English UI**.

## Golden rules

1. **Edit `_src/` only** — never `index.html` / `site/index.html` / `dist/`.
   `index.html` is generated by `build.py` from these sources:
   - `_src/template.html` — HTML skeleton (HUD, modals). Placeholders `/*__CSS__*/` etc.
   - `_src/styles.css` — all styles
   - `_src/data.js` — quest data + combat config (`WEAPONS`, `CHARACTERS`, `SKINS`, `ENEMY_TYPES`, `COMBAT_RULES`)
   - `_src/cloud.js` — cloud account (Email OTP) + progress sync
   - `_src/world.js` — Three.js world, player, combat engine (weapons/enemies/fx/AI), minimap
   - `_src/game.js` — game state, tutorial mission, dialog/dot-cross/vocab, shop economy, HUD, SFX
2. **After every change:** `npm run build` → all 9 checks must PASS (incl. the
   "interface is fully English" gate which fails on legacy Chinese UI strings).
3. **Every change must be re-published to the live link** (fixed link, use `site/`).

## Architecture quick map

- **Combat engine** lives inside `world.js` IIFE (`/* COMBAT MODULE */`):
  weapon factories, enemy models/AI/respawn, attack pose overlay
  (`applyAttackPose` runs AFTER `movePlayer` and overwrites limbs),
  fx (ring/slash/spark/dust/trail), camera shake. Exposed via
  `WORLD.setCombatEnabled / setCombatHooks / spawnEnemies / getEnemies /
   performAttack / equipWeapon / applyCharacterLook / combatState`.
- **Economy & UI logic** in `game.js`: `COMBAT` state (score/gold/weapons/
  characters/skins), `playerAttack` (left-mouse = attack via
  `WORLD.setPrimaryHandler`, `J` kept as backup, `K` = skill), shop tabs
  (`renderShop`/`shopAction`), character switcher (`openCharModal`),
  save: localStorage `bq_combat_v1` + cloud snapshot/apply.
- **Interactive training mission** (`game.js`, replaces text coach):
  `tutStep 1..5` — MOVE (walk 8 m) → APPROACH (<7 m) → PRESS E → ANSWER →
  COMPLETE (then combat unlocks). Persisted as `bq_tut_v1`.
  Big banner `#bigHint` with progress bar `#bhFill`.
- **Left-mouse attack**: `world.js` canvas `mousedown` fires only when
  `document.pointerLockElement === canvas` (prevents misfires in menus).
- **Minimap**: player-centered local view (`MM_VIEW = 130` world units),
  edge arrow when target is off-screen.
- **SFX**: procedural WebAudio in `game.js` (`SFX`, no audio files),
  mute button `#muteBtn` (`bq_mute`).
- **Cloud auth**: `cloud.js` Email OTP, progress table w/ owner-only RLS.
  Works only on the published domain (Origin-bound).

## Known gotchas

- Touch detection: only dual pointer-media-query works
  (`pointer:coarse && !pointer:fine`); `maxTouchPoints`/`ontouchstart` lie.
  Desktop Chrome can be forced with `?touch=1`.
- `build.py` placeholder regex `(CSS|THREE|DATA|CLOUD|WORLD|GAME)` — keep in
  sync if adding a new `_src` file.
- Headless Chrome cannot acquire Pointer Lock; tests fake
  `document.pointerLockElement` to exercise the attack path.
- `npm run ship` may print a sandbox warning AFTER a successful push —
  the push itself succeeds (verify with `git rev-list --count @{u}..HEAD` = 0).
- All visible text must be English; `data.js` `{en, zh}` pairs: render layer
  reads `.en` only (zh values are data-only).
- Player model faces local `+z`; world forward = `(sin rotY, cos rotY)` —
  attack hit-tests rely on this; don't flip the sign.
- Character height 3.26 (head top incl. ahoge); torso pivot y=1.70 is
  hard-coded by animations.
