# 帳號系統 — 鍵界 Bond Quest

## 一、這是甚麼

一個**本機帳號系統**：玩家可以註冊、登入、登出，進度按帳號分開保存，重新進入遊戲時自動載入自己的進度。

它**不是**雲端帳號。原計劃使用 WorkBuddy 雲服務（真正的伺服器端認證 + 跨裝置同步），但開通確認對話框被取消了，因此按工具指示改為本機實作。

| | 本機帳號（現況） | 雲端帳號（未開通） |
|---|---|---|
| 同一瀏覽器重開 | ✅ 進度保留 | ✅ |
| 換電腦／換瀏覽器 | ❌ 沒有 | ✅ |
| 換手機 | ❌ 沒有 | ✅ |
| 資料隔離 | ✅ 加密，冇密碼讀唔到 | ✅ 伺服器端 RLS |
| 忘記密碼 | ❌ 無法重設 | ✅ 可重設 |

需要跨裝置同步時，再開通雲服務即可（`workbuddy_cloud_service` + Auth + Database 模組）。

## 二、資料放哪裡

全部在瀏覽器 `localStorage`，命名空間 `bq_*`：

| Key | 內容 | 加密 |
|---|---|---|
| `bq_accounts_v1` | 帳號清單：電郵、名稱、salt、verifier、加密後的進度 | 進度以 AES-256-GCM 加密 |
| `bq_session_v1` | 本次登入（sessionStorage，關閉瀏覽器即失效） | 含解密金鑰 |
| `bq_session_keep_v1` | 「保持登入」時的同一份資料 | 同上，**明文存於本機** |
| `bq_guest_v1` | 未登入玩家的進度 | 否（訪客本來就沒有密碼） |

帳號記錄長這樣：

```json
{
  "v": 1,
  "accounts": {
    "lukas@example.com": {
      "id": "u_xxxxxxxxxx",
      "name": "Lukas",
      "salt": "base64(16 bytes)",
      "verifier": "base64(32 bytes)",
      "iters": 180000,
      "createdAt": 1795274000000,
      "lastLogin": 1795275000000,
      "data": { "iv": "base64(12)", "ct": "base64(...)" }
    }
  }
}
```

**沒有明文密碼**。實測 `localStorage.getItem('bq_accounts_v1').includes('Passw0rd123')` → `false`。

## 三、密碼與加密怎樣做

一次 PBKDF2 派生兩段金鑰，避免兩次昂貴運算：

```
PBKDF2-SHA256(password, salt = 16 random bytes, iterations = 180,000, dkLen = 64)
  ├─ bytes 0–31  → verifier（儲存，用來核對密碼）
  └─ bytes 32–63 → AES-256-GCM key（用完即棄，只存在記憶體／會話）
```

- 核對用**定時安全比較**（XOR 累加），不是 `===`
- 進度加密：AES-GCM，每次寫入用新的隨機 12-byte IV
- 關鍵效果：**拿到整份 localStorage 也讀不到進度**，因為 verifier 不能反推出 AES key

密碼規則（註冊時檢查）：最少 8 字元、最多 72、必須含英文字母及數字。
電郵：正規表達式 + 長度上限 120。名稱：2–12 字，禁止 `<` `>`。

## 四、登入狀態保持

1. 預設寫 `sessionStorage` → **重新整理仍登入**，關閉瀏覽器即登出
2. 勾「喺呢部裝置保持登入」→ 寫 `localStorage`，可跨瀏覽器重開（**共用電腦唔好勾**）
3. 會話 90 日後自動失效
4. 啟動流程：

```
頁面載入 → 讀 sessionStorage / localStorage
        → 有會話：找回帳號 → 用會話內金鑰解密進度 → 套用
        → 無會話：讀 bq_guest_v1（訪客進度）
```

## 五、防止看到別人資料

| 風險 | 處理 |
|---|---|
| A 登入後 B 在同一瀏覽器打開 | 看到的是 B 自己的訪客進度或登入畫面，**看不到 A 的進度** |
| 有人開 DevTools 抄 localStorage | 進度是密文；冇 A 的密碼解不開 |
| 未登入直接呼叫 API | 沒有 API，也沒有 `AUTH.load()` 以外的讀取路徑；`AUTH.load()` 只會回傳當前會話的資料 |
| 強行改 `bq_session_v1` | 只會解密失敗 → 自動登出（`catch` 後清會話） |

左邊最後一項是這個設計的邊界：**有本機檔案系統存取權的人，可以直接改 JS 或讀取記憶體**。任何純前端方案都無法防住這一點。

## 六、遊戲怎樣接上去

`auth.js` 只透過兩個函數接觸遊戲狀態（`game.js` 內）：

```js
AUTH.init({
  snapshot: snapshotProgress,   // 取出 { done, correct, freePass, wp, beacon, coach }
  apply: applyProgress,         // 還原並 refreshLocks() / updateHUD() / renderQuestPanel()
});
```

自動保存觸發點：`persist()`（每次答題／事件）、`saveWaypoints()`、`saveBeaconCfg()`、教練卡完成。防抖 700ms，避免每次渲染都加密。

暫停：開啟帳號視窗會 `WORLD.setLocked(true)`，所以打 email 時按 W 不會令角色走動（已實測）。

## 七、UI

- 頂欄 `登` 按鈕（未登入）／名字首字（已登入）
- 彈窗兩個分頁：登入 / 註冊
- 每個欄位下方獨立錯誤訊息，不是 `alert`
- 登入後面板：頭像、名稱、電郵、完成節點／答對題數／傳送錨點／最後保存時間
- 操作：匯出進度（JSON）、刪除帳號、登出
- 首次登入若帳號未有資料而本機有訪客進度 → 詢問是否匯入

## 八、已知限制

1. **不跨裝置** —— 換電腦／手機就沒有進度（要雲服務才能解決）
2. **忘記密碼無法救回** —— 沒有伺服器，沒有重設流程；只能刪除帳號重來
3. **保持登入 = 金鑰在本機** —— 共用電腦請勿勾選
4. **清除瀏覽器資料 = 全部消失** —— 建議定期用「匯出進度」備份
5. **私隱模式下 localStorage 可能不可用** —— 會提示「進度唔會自動保存」

## 九、驗收紀錄（2026-11-21）

| 測試 | 結果 |
|---|---|
| 空表單提交 | 三個欄位各自顯示錯誤 |
| 格式錯誤 / 短密碼 / 短名稱 | 正確攔截並提示 |
| 註冊 | 成功，頂欄變 `L`，`data` 有 iv+ct |
| 明文密碼檢查 | `false` |
| 完成一個節點後重載 | 仍登入，計數 1、任務完成 1（進度還原） |
| 登出 | 回到訪客，計數 0 |
| 錯誤密碼 | 「密碼唔正確」，未登入 |
| 正確密碼 | 進度回來（計數 1） |
| 開窗期間按 W | 角色不動（`locked: true`） |
| Esc | 關窗並解鎖 |
